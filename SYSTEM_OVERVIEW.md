# Configuration Dialog System - Complete Overview

## System Architecture

The configuration dialog system consists of three integrated layers:

```
┌─────────────────────────────────────────────────────────┐
│   egui Integration Layer (config_dialog_egui.rs)        │
│   ─ render_field() / render_section()                   │
│   ─ render_dialog() / render_multi_section_dialog()     │
│   ─ Widget selection and UI rendering                   │
└──────────────────────┬──────────────────────────────────┘
                       │ uses
┌──────────────────────▼──────────────────────────────────┐
│   UI Integration Layer (config_dialog_ui.rs)            │
│   ─ ConfigFormState (tracks values & dirty fields)      │
│   ─ FormValidator (validates against constraints)       │
│   ─ SuggestedWidget (recommends UI widgets)             │
│   ─ FormValue enum (type-safe form values)              │
└──────────────────────┬──────────────────────────────────┘
                       │ uses
┌──────────────────────▼──────────────────────────────────┐
│   Metadata Framework (config_dialog.rs)                 │
│   ─ FieldMetadata (field descriptions & types)          │
│   ─ FieldType enum (Bool, Float, String, Enum, etc.)    │
│   ─ EnumVariantMetadata (enum option descriptions)       │
│   ─ ConfigSectionMetadata (groups of fields)            │
│   ─ ConfigMetadata trait (provides metadata)            │
└──────────────────────┬──────────────────────────────────┘
                       │ generated by
┌──────────────────────▼──────────────────────────────────┐
│   Build-Time Generation (build.rs)                      │
│   ─ Parses src/config.rs using syn crate                │
│   ─ Extracts doc comments and field types               │
│   ─ Generates ConfigMetadata implementations            │
│   ─ Outputs to target/OUT_DIR/config_metadata.rs        │
└─────────────────────────────────────────────────────────┘
```

## Data Flow

### 1. Build Time
```
config.rs (with /// doc comments)
    ↓ [build.rs parses]
    ↓
syn AST (struct definitions, comments)
    ↓ [code generation]
    ↓
config_metadata.rs (ConfigMetadata trait implementations)
    ↓ [include! macro]
    ↓
libsurfer::config_metadata module
```

### 2. Runtime
```
ConfigMetadata::metadata() retrieves ConfigSectionMetadata
    ↓
ConfigFormState initialized with field values
    ↓
render_dialog() calls render_section() calls render_field()
    ↓
egui widgets created and form state updated
    ↓
User edits fields, form tracks dirty_fields
    ↓
User clicks OK/Cancel
    ↓
Application applies changes or discards
```

## Module Responsibilities

### `config_dialog.rs`
**Purpose:** Define the type system for field metadata

**Key Types:**
- `FieldType` - Enum of supported field types with constraints
- `FieldMetadata` - Describes a single configurable field
- `EnumVariantMetadata` - Describes enum variant options
- `ConfigSectionMetadata` - Groups related fields
- `ConfigMetadata` trait - Provides metadata for config structs
- `FieldMetadataBuilder` - Fluent API for creating metadata
- `ConfigMetadataRegistry` - Registry of all sections

**Generated by:** Manual implementation of `ConfigMetadata` for config structs (via build.rs)

**Used by:** config_dialog_ui, config_dialog_egui

### `config_dialog_ui.rs`
**Purpose:** Manage form state and validation

**Key Types:**
- `ConfigFormState` - Tracks user edits, dirty fields, errors
- `FormValue` - Type-safe enum for all value types
- `FormValidator` - Validates values against constraints
- `SuggestedWidget` - Recommends appropriate egui widget
- `ConfigDialogBuilder` - Organizes fields for rendering

**Dependencies:** config_dialog.rs

**Used by:** config_dialog_egui, applications

### `config_dialog_egui.rs` (NEW)
**Purpose:** Render configuration dialogs using egui

**Key Functions:**
- `render_field()` - Render single field with appropriate widget
- `render_section()` - Render all fields in a section
- `render_dialog()` - Complete dialog with OK/Cancel
- `render_multi_section_dialog()` - Multiple sections in tabs

**Key Types:**
- `DialogConfig` - Configure rendering behavior
- `DialogResult` - Applied/Cancelled/Pending result

**Dependencies:** config_dialog.rs, config_dialog_ui.rs, egui

### `build.rs`
**Purpose:** Generate metadata from config.rs at compile time

**Entry Point:** `generate_config_metadata_from_source()`

**Parsing Steps:**
1. Read `src/config.rs`
2. Parse with `syn` crate (AST)
3. Find config structs (SurferLayout, SurferBehavior, etc.)
4. Extract doc comments as descriptions
5. Infer field types from Rust types
6. Generate `ConfigMetadata` implementations
7. Output to `target/OUT_DIR/config_metadata.rs`

**Recognized Structs:**
- SurferLayout
- SurferBehavior
- SurferConfig
- SurferGesture
- SurferTheme
- WcpConfig

## Integration Points

### Adding a New Config Struct

1. **Define in config.rs:**
```rust
/// User interface preferences
#[derive(Debug, Deserialize)]
pub struct UserPreferences {
    /// Show expert options
    pub show_expert_mode: bool,
    /// Custom color scheme (RGB)
    pub accent_color: [u8; 3],
}
```

2. **Update build.rs:**
```rust
// In is_config_struct() function, add:
name.ident.to_string() == "UserPreferences"
```

3. **Use in application:**
```rust
use libsurfer::config_metadata::UserPreferencesMetadata;
let metadata = UserPreferencesMetadata::metadata();
let mut form = ConfigFormState::with_metadata(&metadata);
```

### Using in an Application

```rust
use libsurfer::config_metadata::*;
use libsurfer::config_dialog_ui::ConfigFormState;
use libsurfer::config_dialog_egui::*;

fn main() {
    let mut app = MyApp::new();
    eframe::run_native("Surfer", options, Box::new(|_cc| Box::new(app)));
}

impl eframe::App for MyApp {
    fn update(&mut self, ctx: &egui::Context, _frame: &mut eframe::Frame) {
        if self.show_settings {
            self.render_settings(ctx);
        }
    }
}

impl MyApp {
    fn render_settings(&mut self, ctx: &egui::Context) {
        let metadata = SurferLayoutMetadata::metadata();

        egui::Window::new("Settings").show(ctx, |ui| {
            let result = render_dialog(
                ui,
                "Layout",
                &metadata,
                &mut self.layout_form,
                &DialogConfig::default(),
            );

            match result {
                DialogResult::Applied => {
                    // Apply changes to config
                    self.apply_changes();
                    self.show_settings = false;
                }
                DialogResult::Cancelled => self.show_settings = false,
                DialogResult::Pending => {}
            }
        });
    }
}
```

## Usage Patterns

### Pattern 1: Simple Dialog
```rust
let metadata = SurferLayoutMetadata::metadata();
let mut form = ConfigFormState::with_metadata(&metadata);

egui::Window::new("Settings").show(ctx, |ui| {
    match render_dialog(ui, "Layout", &metadata, &mut form, &config) {
        DialogResult::Applied => apply(form),
        DialogResult::Cancelled => {},
        DialogResult::Pending => {}
    }
});
```

### Pattern 2: Multi-Section Dialog
```rust
let sections = vec![
    SurferLayoutMetadata::metadata(),
    SurferBehaviorMetadata::metadata(),
];

match render_multi_section_dialog(ui, "Settings", &sections, &mut form, &config) {
    DialogResult::Applied => apply_all(form),
    DialogResult::Cancelled => {},
    DialogResult::Pending => {}
}
```

### Pattern 3: Field-by-Field Rendering
```rust
for field in &metadata.fields {
    if render_field(ui, field, &mut form, &config) {
        // Field changed
        println!("Field {} changed", field.name);
    }
}
```

### Pattern 4: Change Tracking
```rust
// Track which fields changed
for field_name in form.dirty_fields.keys() {
    println!("User modified: {}", field_name);
}

// Get changed values
let changes: HashMap<_, _> = form.dirty_fields
    .iter()
    .filter_map(|(name, _)| {
        form.values.get(name).map(|val| (name.clone(), val.clone()))
    })
    .collect();
```

## Troubleshooting

### Issue: Metadata not generated
**Solution:** Check that struct name is in `is_config_struct()` in build.rs

### Issue: Field not showing in dialog
**Solution:**
- Ensure struct has `#[derive(Debug, Deserialize)]`
- Add `/// Documentation` comment to field
- Verify field type is in the supported list

### Issue: Values not persisting
**Solution:**
- Call `render_dialog()` with mutable `form_state`
- Get values from `form_state.values` before discarding
- Ensure you're not resetting form after applying changes

### Issue: Color picker not working
**Solution:**
- Use `FormValue::Color([r, g, b])` with values 0-255
- Check egui context color space settings
